# v0.15

## 版本目标

本版本根据 `role-md/code-agent.md` 新增的养成进度存档规范，补上第一版正式本地长期存档和数据库层。局外养成数据不再由各系统直接写旧文件，而是统一通过 `SaveManager` 管理，并把长期进度、设置和单局统计拆开保存，同时同步到本地结构化数据库，附带服务端 MySQL 建表脚本。

## 本次新增内容

- 新增 `SaveManager` 统一管理本地长期存档
- 新长期存档路径：`user://save_data.json`
- 新设置存档路径：`user://settings.json`
- 新单局记录路径：`user://run_records.json`
- 新本地数据库路径：`user://local_database.json`
- 新增服务端 MySQL schema：`database/schema_mysql.sql`
- 存档增加 `version` 字段，预留后续迁移
- 首次启动会生成默认存档和默认设置
- 存档损坏或解析失败时会回退到默认结构，避免启动崩溃
- 旧版 `user://meta_progression.save` 会自动迁移到新版存档
- 结算时写入长期碎片收益，并独立记录本局统计
- 首页支持显示 SaveManager 计算出的离线收益提示
- 数据库层落地 `player_saves`、`player_settings`、`run_records` 三张结构化表

## 具体调整

- `scripts/core/database_manager.gd`
  - 新增本地结构化数据库管理器
  - 维护 `player_saves`、`player_settings`、`run_records`
  - 支持存档 upsert、设置 upsert、单局记录 insert
  - 当主 JSON 存档缺失时，可作为恢复来源
- `database/schema_mysql.sql`
  - 新增 MySQL 8 建表脚本
  - 覆盖 `player_saves`、`player_settings`、`run_records`
  - 为 run_id、player_id、character_id、branch_id 和 created_at 提供索引
- `scripts/core/save_manager.gd`
  - 新增统一存档入口
  - 保存长期进度、货币、解锁、人物成长、基地、研究、离线时间和偏好字段
  - 保存设置默认结构
  - 保存单局 RunRecord，并限制本地记录数量
  - 提供旧 `meta_progression.save` 迁移逻辑
  - 写入 JSON 主存档时同步写入 `DatabaseManager`
  - 主 JSON 存档缺失时优先尝试从本地数据库恢复
- `scripts/core/meta_progression.gd`
  - 移除直接读写旧存档文件
  - `load_or_create()` 改为从 `SaveManager.load_progression_state()` 读取
  - `save()` 改为通过 `SaveManager.save_progression_state()` 写入
  - 新增 `record_run()`，通过 SaveManager 写入独立单局记录
- `scripts/core/game_manager.gd`
  - 一局结束后构建 RunRecord
  - 长期碎片收益和单局统计分开保存
  - RunRecord 记录人物、流派、等级、击杀、时长、Boss 状态、碎片收益、局内升级和特殊卡
- `scripts/ui/home_panel.gd`
  - 首页碎片区域会显示本次加载时计算出的离线收益
- `README.md`
  - 同步 v0.15 存档系统状态

## 已知问题

- 第一版数据库为 Godot 本地 JSON 数据库，服务端 MySQL 目前提供 schema，尚未接入 CloudSaveManager
- 本地防篡改只做了字段回退和范围校验，尚未加入签名、hash 或加密
- 离线收益目前为本地时间第一版实现，正式联网版本仍应以服务器时间为准
- 建筑、研究、金币、材料等字段已预留结构，但当前 UI 尚未开放对应玩法入口
